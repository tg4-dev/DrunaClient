# Вход и регистрация

Источники: `lib/app/druna_app.dart`, `lib/app/session_controller.dart`, `lib/features/auth/auth_screen.dart`.

## Splash

Пока `SessionState.restoring`, показывается `GradientScaffold`: марка 72 и `CircularProgressIndicator`. Сеть на этом экране не обязательна: решение «есть ли пара токенов» локальное. Профиль запрашивается уже после перехода в `signedIn`.

## Welcome

Стартовый режим `AuthScreen` — не форма, а два действия и заглушка.

- Заголовок: «Найдём время для встречи». Подзаголовок: «Сверим календари и покажем удобные окна».
- «Войти» переключает тот же экран в режим формы (`_loginMode = true`), без нового route.
- «Создать аккаунт» открывает `SignupScreen`.
- «Ответить на приглашение без аккаунта →» не вызывает API. Сообщение: «Гостевые опросы появятся после добавления endpoint на сервере».

Клавиатура прячется свайпом по скроллу.

## Вход

Поля: «Ник или почта» (autofill username и email, без autocorrect) и «Пароль» с переключателем видимости. Submit с клавиатуры на пароле вызывает вход.

Валидация до запроса:

- ник после trim не пустой, иначе «Введи ник»;
- пароль не пустой (минимальной длины на входе нет), иначе «Введи пароль».

Запрос: `session.signIn` → `POST /auth/sign-in` с trim только у username, затем `GET /api/v1/users/me`. Успех сам сменяет home на `HomeScreen`, экран вход не закрывает вручную.

На время запроса кнопка «Войти» в состоянии loading. Ошибка — snackbar с `error.toString()` (это текст `ApiException`).

«Не помню пароль» не вызывает API. Текст: «Восстановление пароля пока не поддерживается сервером».

## Регистрация

`SignupScreen`, app bar «Создать аккаунт». Декоративные точки шага есть, шагов формы одна.

Поля и правила:

| Поле | Правило | Сообщение |
|---|---|---|
| Имя | trim не пустой | «Введи имя» |
| Почта | trim матчит `^.+@.+\..+$` | «Проверь адрес почты» |
| Ник | trim длиной ≥ 3 | «Минимум 3 символа» |
| Пароль | длина ≥ 8, без trim | «Пароль должен быть не короче 8 символов» |

Подпись под кнопкой: «Продолжая, ты принимаешь условия использования». Отдельного экрана условий нет. Текст «После регистрации Druna автоматически назначит твой постоянный цвет» — только копирайт, цвет с сервера не читается и не пишется.

Успех: `signUp` (регистрация и сразу вход), затем `popUntil` до первого route. К этому моменту сессия уже `signedIn`, первый route — главная.

Ошибка на любом из двух запросов остаётся на форме регистрации, сессия не становится `signedIn`, если `signIn` внутри `signUp` не завершился (токены пишутся только после успешного sign-in).

## Что UI не делает

- Не восстанавливает пароль.
- Не входит гостем и не открывает опрос по ссылке.
- Не проверяет токен на splash отдельным запросом до показа главной.
