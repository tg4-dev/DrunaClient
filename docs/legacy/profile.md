# Профиль

Источник: `lib/features/profile/profile_screen.dart`.

Экран называется «Настройки». Данные берутся из `session.profile`, который заполняется при восстановлении сессии и при входе. Если профиля ещё нет, экран сам вызывает `refreshProfile` (`GET /api/v1/users/me`) и подставляет имя и URL в поля. Ошибка этой загрузки — snackbar.

## Что показывается

- аватар: картинка по `avatarUrl`, иначе буква имени и цвет от `id`;
- `@username` или слово «Профиль», если профиля нет;
- email, если строка не пустая. Email только для чтения, в PATCH не уходит. Username тоже не редактируется.

## Сохранение

Поля: «Имя» и «Ссылка на аватар» (`https://…`, клавиатура URL). Кнопка «Сохранить».

Пустое имя после trim блокирует запрос: «Имя не может быть пустым». Формат URL клиент не проверяет.

`updateProfile(name, avatarUrl)` шлёт PATCH с обоими полями, если они переданы (экран передаёт оба всегда, в том числе пустой `avatarURL`). Затем снова GET профиля и snackbar «Профиль обновлён». Ошибка — snackbar, сессия не меняется, пока GET после успешного PATCH не упадёт: тогда PATCH уже прошёл, а локальный профиль может остаться старым, если `refreshProfile` бросил исключение.

## Блоки без API

- Карточка «Приватность по умолчанию»: «Друзья видят только свободные окна, а не содержимое событий». Это текст, переключателя и запроса нет.
- «Внешние календари», подпись «Интеграция ожидает backend endpoint». Тап: «Backend пока не предоставляет подключение Apple, Google или Outlook Calendar». Успех не показывается.
- «Сервер» показывает `APP_ENV` и `API_BASE_URL` текущей сборки. Это не настройка, адрес из UI не меняется.

Загрузки файла аватара нет: сервер принимает уже размещённый URL в поле `avatarURL`.

## Выход

«Выйти» спрашивает «Выйти из аккаунта?» и объясняет, что токены и приватные данные сессии будут удалены с устройства. Подтверждение закрывает экран настроек и вызывает `session.logout()`: локальная очистка пары, без запроса на сервер. Отмена оставляет сессию.
